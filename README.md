# LogWatch

An OpenTelemetry-based tracing and evaluation pipeline for LLM
applications, demonstrated against QueryGuard.

Status: Phase 1 complete. Storage, dashboards and read API run on
synthetic data; real telemetry arrives in Phase 4.

## Run locally

    cp .env.example .env
    make up
    make venv
    make migrate
    make seed

## Ports

| Service  | URL                     |
|----------|-------------------------|
| Grafana  | http://localhost:3001   |
| API docs | http://localhost:8001/docs |
| Postgres | localhost:5433          |

All bound to 127.0.0.1 only. See `docs/adr/0003-non-default-ports.md`.

## Make targets

| Target             | What it does                                |
|--------------------|---------------------------------------------|
| `up` / `down`      | start / stop the stack (data survives)      |
| `nuke`             | stop and delete volumes (data is destroyed) |
| `migrate`          | apply pending SQL migrations                |
| `seed`             | generate synthetic telemetry                |
| `purge-synthetic`  | delete all synthetic rows                   |
| `api-rebuild`      | rebuild and restart the API container       |
| `psql`             | open a psql shell in the database           |

## A note on the data

Every row currently in the database is **synthetic**, generated by
`scripts/seed.py` and labelled `environment='synthetic'`. The scenario
mix is invented for dashboard development and is not a measurement of
QueryGuard's behaviour. Measured figures appear in Phase 6, after the
real pipeline is live and the synthetic rows have been purged.
